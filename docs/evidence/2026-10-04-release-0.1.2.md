# Mobile Webcam 0.1.2 release validation

Date: 2026-10-04. The release introduces saved desktop settings, combined USB
startup, simpler Android controls and an experimental Windows installer.

## Executed checks

- Linux host: Release build with warnings treated as errors; all five CTest
  cases passed on CachyOS. The GUI test opens a separate process and checks
  restoration of the Wi-Fi address, transport, rotation and flips. USB startup
  and cancellation use isolated fake helper processes, without touching a phone.
- Windows host: MinGW cross-build with warnings treated as errors; six CTest
  cases passed under Wine 11.18. A further GUI run verified persistence through
  Windows QSettings NativeFormat (the registry), with an isolated test key.
- Windows Setup.exe: Wine install, update, uninstall, both registry views,
  foreign-camera collision refusal, locked-file retry and user-file retention
  passed. The installed payload contains the app, two operational helpers,
  runtime DLLs and the pinned Unity Capture filters; it contains no BAT files
  or video-dump/debug utility.
- Android: signed `assembleRelease lintRelease` passed with JDK 17, Gradle 8.9
  and SDK 35. Package version is 0.1.2 / versionCode 1002. The signing certificate
  matches the existing 0.1.1 release, so the APK can upgrade that installation.
- Linux release packaging uses Debian 13, Qt 6.8.2, FFmpeg 7.1.5 and libusb
  1.0.28. The native AppImage build runs CTest. libusb, the C++ runtime, Qt
  platform-plugin dependencies, the setup helper and license notices are bundled.
  Dependency inventories and corresponding Debian/MSYS2 source archives accompany
  the release. Debian source downloads were checked against repository SHA-256
  metadata; every release asset is listed in `SHA256SUMS`.
- The exact AppImage started on the CachyOS desktop under both native Wayland
  and an X11 Xvfb display, with isolated settings. Each run remained active until
  its bounded test stop, without Qt loader errors. ELF inspection found a maximum
  glibc requirement of 2.39 and only x86-64-baseline ISA requirement notes. The C++
  runtime is bundled. This proves startup on these environments, not camera flow
  or compatibility with every distribution.
- Shell parsing and `git diff --check` passed. Independent code review's CRLF
  test finding was fixed and verified on Windows; the focused follow-up found
  no further actionable defects.

## Boundaries

Fresh phone streaming, Android rotation/permission UI, privileged Linux setup
on a clean installation, and sustained Wi-Fi/reconnect tests are **NOT RUN**.
The earlier Xperia/Discord USB evidence remains historical.

Actual Windows UAC, USB driver binding, D3D11VA and consumer-camera applications
are **NOT RUN**. Wine validates the installer logic and host/GUI behavior; it
does not replace these hardware checks. Wine screenshot review also found missing
Japanese glyphs in that environment; native Windows font rendering is unverified.

GUI fixture screenshots show a test camera path and disabled configuration
controls. They are behavioral-test captures, not physical camera evidence.

GitHub Actions is **NOT RUN** for this release: the repository has no registered
self-hosted runner. The release is built and verified locally using the existing
Android signing key. The queued tag workflow is canceled after local publication
to prevent a delayed duplicate release.
